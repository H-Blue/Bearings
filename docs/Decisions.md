# ReCollect decisions

Status: approved direction and routine decisions reconciled with implemented source, October 10, 2026. Verification results and outstanding limitations are maintained separately in `docs/Testing.md` and `docs/Progress.md`.

| Decision | Why | Consequences and alternatives |
| --- | --- | --- |
| Use ReCollect as the application name. | The owner's explicit current brief establishes that name. | Preserve existing Notion titles; `Reco`, `HeartMap` and Project Wayfinder are older reference names. |
| Native SwiftUI with SwiftData, iOS 17 or later. | Matches the approved native stack and provides local persistence without dependencies. | SwiftData requires iOS 17. Older iOS support would require a different storage approach and is outside this foundation. |
| Use conventional responsibility-based Swift folders and type names. | Makes the current ReCollect code easy to navigate and maintain. | The Notion guide's older `pw_` code/folder convention remains recorded in reference research. Existing artwork may retain its original paths. |
| Three explicit periods: morning left, midday top, evening right. | The owner clarified the circle meanings. | Persist the selected period as `periodRawValue`. A branch opens the latest matching entry or creates a draft; Write creates another with an editable local-time suggestion. |
| Use Apple's system font and native text editing. | The owner approved replacing Inter; native editing supports keyboard behavior and accessibility. | Preserve Figma composition and palette while documenting the approved typography difference. |
| Use native dynamic drawing for the timeline and branches; retain Figma editor SVGs. | The graphs must reflect actual dates and entries and adapt to phone sizes, while the editor's oval and rule are reusable assets. | Timeline/day SVGs remain inspectable references. `EditorCircle.svg` and `EditorRule.svg` are vector imagesets used by the application. |
| Store a Gregorian civil `dayKey` separately from timestamps. | Writing belongs to the selected day; traveling must not move earlier entries to a different calendar date. | Creation and modification times remain absolute instants. Validate day keys and handle calendar conversion carefully. |
| Store the browsed month as `JournalMonth` civil components; format civil labels in UTC. | A month selection must not shift backward when the device moves to another time zone, and month enumeration must include skipped civil dates. | Direct Gregorian enumeration includes leap days and avoids local-midnight arithmetic. Bounds are years 1–9999. |
| Dedicated local SwiftData store, CloudKit disabled. | The MVP is private, offline and intentionally focused. | Cloud sync remains future scope. Store initialization failures are visible; never silently use temporary storage in production. |
| Protect the store with `completeUntilFirstUserAuthentication`. | Provides native iOS data protection while allowing normal journaling after the first device unlock. | Protect the directory and store companion files; physical-device protection still requires device verification. |
| Keep the editor draft separate and explicitly commit each mutation in a fresh context. | Failure fixtures exposed SwiftData registered-model/cache behavior that shared-context rollback did not reliably restore. Isolation keeps failed creates, edits and deletions out of the context observed by the interface. | Resolve edits/deletions by UUID; rollback and discard failed transactions. Mirror edits into the original model only after a successful commit. Autosave is disabled; no native undo manager is used. |
| Fetch committed records with `includePendingChanges = false` in store reads and the root query. | Drafts and failed mutations must not masquerade as saved journal data. | Root query loading failures show retry rather than an empty timeline. Missing entry UUIDs fail visibly rather than creating replacement records. |
| Request autosave after 350 ms, and save on Done, scene inactivity and editor disappearance. | Reduces the chance of losing active edits while keeping writing responsive. | Actual save success drives UI state; unsaved drafts block interactive dismissal. Lifecycle saving cannot guarantee recovery after an abrupt termination before a save completes. |
| Do not insert new blank drafts; allow existing entries to be cleared. | Opening and closing an unused editor should not create journal data. Editing an existing entry must not silently delete it. | Explicit deletion is a separate confirmed action. Test both paths. |
| Make successful deletion terminal in the editor session; retry deletion failures separately. | Pending save callbacks must not resurrect a deleted entry, and a deletion retry must perform the operation the user requested. | Draft retention supports retry after failure; confirmed successful deletion clears the session. |
| Scale timeline to 1.8 around the tapped date, offset it −180 points; introduce day from +160 points. | Preserves the approved zoom/upward navigation relationship with native animation. | Forward/reverse use spring response 0.55 and damping 0.88. Reduce Motion uses a 0.18-second fade; no matched-geometry effect is used. Explicit paper/timeline/day z-indices 0/1/2 preserve the exiting day's visibility during reverse navigation. Visual evidence is recorded separately. |
| Use native Dynamic Type, scaled timeline cells, and vertical scrolling at accessibility sizes. | Enlarged date numbers need physical layout space, and larger text and controls must remain reachable on compact phones. | Native caption scaling expands cell width and cell/viewport height from the baseline proportions. Date labels retain a single-line intrinsic size without a font cap; dates remain horizontally scrollable within vertical content. Visual verification is recorded separately. |
| Share marker-area height across the browsed month and expand it for three dots or overflow counts. | Fixed marker space can clip the three dots plus a remaining-count label, especially above minor ticks. | Use the month's largest entry count to keep ticks aligned: 70 points up to two entries, 75 for three, and 80 plus a native caption2-scaled allowance for overflow. Cell and viewport heights grow together. |
| Use a compact editor header at accessibility4/5 and place keyboard dismissal in the saving footer. | Date, period, writing and keyboard controls must remain usable together at the largest native text sizes. | Omit the decorative oval and use scalable caption metadata at those sizes; keep journal body text at scalable title3. Hide keyboard uses a native icon with a 44-point hit target in the normal layout. |
| Back day-period labels with the paper color. | Decorative branch lines must stay clear of readable labels. | Preserves the inspected branch structure while making text clearer at native accessibility sizes. |
| Provide a local read-only retrieval interface without AI runtime. | Keeps later reflection work possible without premature infrastructure. | No journal content leaves the device. AI, export, sync and other future integrations need later approval. |
| Maintain local architecture/product/decision/test/progress documents and synchronize milestones to Notion. | Another developer should be able to continue without reconstructing the conversation. | A milestone is incomplete until documentation is accurate or pending synchronization is explicitly recorded. Notion writes require saved-content verification before claiming they occurred. |

No paid services, external publication, cloud features, gamification, or AI capabilities were approved as part of these decisions.
